KNOWN DEFINITIONS (the rules the code is meant to follow)
- Entry = close of the confirmation bar, three bars after the trough bar. Date fields are the confirmation close date; low_date is the trough bar's open date, low_day the calendar day of the low.
- Regime gate: regimes.rsi_regime('data/BTC_2D.csv', 8, 13, 60, 41), read on the trough bar's open date.
- Forward window: daily candles, the 60 calendar days after the entry date. Rose 10% = a daily high >= entry x 1.10. Never fell 25.3% = no daily low <= entry x 0.747. Within a day the low is taken before the high.
- Rounding: rounding.rnd, half away from zero on the stored number's binary float (same as JS toFixed), once.
- 2D-8D bars bucket days within each calendar year, restarting on 1 January.
- "Known by then": a past signal counts once entry + 60 days is on or before the date in question.
- The posting / edge bar is 70%, tested on exact shares. "must close above" is rounded down to the cent.
- The page uses each file only if it passes the strict check (FEED_SCHEMA in the page; feedcheck.py reads the same block; feed_live.py refuses to publish a feed that fails).
- The run seal (seal.py): nothing in datasets/ may change between scoring steps.
