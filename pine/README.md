Every Pine source in the project's history, rescued 22 Oct 2026 from a working
directory that was never committed. Before this, the repo held only
`ctzb_scanner_v8/v9` under `docs/reference/` — **the indicator itself was not

## v16 / v10 - DRY RUN, not yet published (29 Oct 2026)

`ct_zone_bounce_v16.pine` and `ctzb_scanner_v10.pine` are GENERATED by
`build_v10.py` from one engine (`engine_v10.pine.in`) and two templates
(`indicator_v16.pine.in`, `scanner_v10.pine.in`). Edit the `.in` files and rebuild;
never edit the generated files. The build re-derives every BTC card in
`datasets/cards.csv` and the ETH price-only grades in `analysis/RESULTS_fundloss.md`
from the tables it embeds, and refuses to build on any difference.
`pine_mirror.py` replays the engine's rules in Python on the repo's candles and must
match every live card (forming, dates, bars needed, kill close, confirmations).

Both scripts show the console's trade card (docs/CARD_SPEC.md). BTC grades are the
console's exactly. ETH is graded without funding (TradingView cannot read the
12-exchange funding), shown with an asterisk, with that price-only grade's own record
from 2016 (Jared, 29 Oct: Joe must see grades without setting anything; the console's
ETH grade stays official). Each card has a copy line to paste to Claude for the
console's card. Card numbers freeze at the build date; rebuild to refresh.
Jared is dry-running them; v15 and scanner v9 stay what is shared with Joe.

## The forecast cone — not in use

Tried 22 Oct 2026 and set aside by Jared: the bands hold up but carry no
direction, and the median is price shifted forward. Kept as the record.

`ctzb_forecast_cone.pine` (22 Oct 2026, v1.1) draws the adopted volatility-scaled
forecast range (`analysis/volrange.py`) on the price pane: a cone 14/30/60/90
days forward, the band each bar was forecast to land in (offset onto the bar
it was for, stopping at the last candle; the past median line is a toggle, off
by default), and a table with today's levels and the indicator's own live
track record. One script for 1D, 2D and 3D charts; it detects the timeframe and
always computes on daily bars underneath, so the numbers are the same on every
chart. It carries the mechanical regime gate (BTC 2D CT RSI control zone)
inside itself; it does not read any other indicator.

`analysis/cone_mirror.py` is a bar-for-bar Python replica. Its printout is what
the table should show (track record within a few tenths; n a day or two higher
as the chart moves on, plus one for the forming day, which the table scores
provisionally). Reviewed line by line against the Pine v6 docs on 22 Oct 2026;
one bug fixed (`barstate.isconfirmed` does not work inside `request.security`).
Known cosmetic limit: on 2D/3D the past-forecast band can sit one day early
where its target crosses 1 January, because those bars restart on New Year.
**Not yet confirmed compiling** — paste and check.

## Warning

`engine.py` is the Python reimplementation of this indicator and the two must
agree. If a Pine file changes in a way that moves a signal, `engine.py` has to
move with it, and `troughs.json` and `odds.json` need regenerating. The
definitions in `CONTEXT.md` are the contract between them.
